# CLAUDE.md — Aristea Timeline

## Правила работы
1. Спрашивай вместо того чтобы угадывать
2. Пиши минимальный код
3. Делай только то о чём прошу
4. Фокусируйся на результате, а не инструкции
5. Работай аккуратно и внимательно
6. Код не пиши пока я не скажу, отвечай кратко
7. **Мерж и деплой.** До публикации (RuStore или сайт, открытый для людей):
   если CI зелёный — мёржи и выкатывай сам, если в задании не сказано иначе.
   После публикации — только по моему слову.
8. **Новая сессия.** В конце каждого отчёта последней строкой — одно из двух:
   «Сессию можно продолжать» или «Нужна новая сессия» и причина. Новая сессия
   нужна, если: контекст заполнен больше чем наполовину или следующая задача
   на другую тему. После деплоя сама по себе — не нужна (05.10.2026). Перед
   «Нужна новая сессия» обнови `docs/handoff.md` в ветке `wip/tariffs-pdf`
   (что сделано, что не проверено, что дальше), и в итоге `notify.py` тоже
   укажи «нужна новая сессия». Если в ходе работы контекст подходит к половине —
   остановись в безопасной точке и сделай то же самое, не доводя задачу.
9. **Режим до публикации** (30.09.2026). Новые функции — только за флагом,
   выключенным на проде до моего слова. Одно задание — одна правка, без
   «по ходу пришлось поменять». Крупное — сначала отчёт и план. Исправления
   ошибок — без флага. Как — [docs/flags.md](docs/flags.md).

## Экономия контекста (05.10.2026)

- **CI и деплой не ждать** (06.10.2026): запустил — завершил ход. Итог
  ручного деплоя приходит владельцу сам — джоб `notify-deploy` в `ci.yml`
  (успех, «не начат», падение, код `/health`). Автомёржа в репозитории нет
  (`--auto` отклоняется) — свой PR мёржится в начале следующего хода, если
  CI зелёный.
- **Отчёт владельцу ≤ 15 строк:** PR/коммит; CI/деплой; Consistency одной
  строкой (прод / под флагом); отклонения от задания; вопросы. Подробности —
  в PR и `docs/handoff.md`, не в отчёте.
- Файл Consistency владельцу — только если «новых > 0».
- Локально — только затронутые тесты: `pytest -q -x --tb=short`; полный
  набор — CI. Логи — `--log-failed | tail`; диффы — сначала `--stat`.
- Поиск по коду — через субагента; карта ядра `sky` и вызовов —
  [docs/map.md](docs/map.md). Файлы читать по `grep` и диапазонам строк.
- Отчёт Consistency — только таблица и «новые / ушло», «Утро» целиком не
  читать.
- Новая сессия — при смене темы или после половины контекста, не после
  каждого деплоя (п. 8).

## Голос продукта

⚠️ **Слова «AI» и «ИИ» в пользовательских текстах не употребляются** (решение
владельца 17.09.2026). Единый словарь замен — в TASKS.md, «Слово „AI“ убрано».

⚠️ **Одно понятие — один термин** (решение владельца 28.09.2026): «Разбор
карты» (не «интерпретация»), «Разбор транзитов» (не «разбор аспектов» и не
«расшифровка транзита»), «Экспорт событий в Google Календарь». Глубина
тарифа — значением («около 2500 слов»), а не отдельным словом. Словарь
витрины — `docs/tariffs.md`, «Витрина».
Исключение ровно одно: юридические документы (политика и текст согласия),
где слово называет получателя данных при трансграничной передаче, — там оно
остаётся намеренно.

⚠️ **Продукт обращается к человеку на «ты»** (решение владельца 24.09.2026):
веб, приложение, уведомления, письма, ошибки API и тексты моделей. Держит
`backend/tests/test_informal_address.py` — сканирует литералы Python, строки
JSON и JS/JSX без комментариев на «вы/ваш», «-йте» и глаголы второго лица
(«можете»). На «вы» намеренно: оферта, политика, текст согласия; всё, что
видят КЛИЕНТЫ астролога (портал, анкета, письма под брендом астролога,
страница отписки) — это голос астролога; сообщения владельцу. Файл целиком —
`ALLOWED_FILES` с причиной, строка — маркер `вы-разрешено` в комментарии.
Промпты берут одну строку `ADDRESS_RULE` (`interpretation/address.py`), тест
требует её в каждом промпте, текст которого читает человек.

⚠️ **«Ты» не должно угадывать пол.** Пола человека мы не знаем: «ты рано
узнал», «ты уверен», «будь осторожен» переписываются без рода («береги себя»,
«тебя не было 5 дней»). Та же оговорка — в `ADDRESS_RULE` и в правилах
прогнозов. С 28.09.2026 в правиле названы и прилагательные («видят тебя
уверенной» → «в тебе видят уверенность»). Отбраковки нет — есть счётчик:
`interpretation/gender_check.py` ловит родовые обороты в разборах карты и
транзитов и в чате, пишет строку в лог и число в сводку самопроверки
(`docs/selfcheck.md`). Сохранённые разборы массово не переписываются.
С 29.09.2026 в правиле и детекторе — краткие формы и «себя + прилагательное»
(«ты склонен», «будешь успешен», «чувствовать себя опустошённым»), а PDF
берёт сохранённый разбор, только если детектор в нём ничего не нашёл, иначе
пишет новый без квоты (`pdf_reports/sections.pick_interpretation`).

## Сервер и деплой — коротко

Полностью — [docs/deploy.md](docs/deploy.md).

- **SSH к серверу у Claude Code нет.** Нужно действие на сервере — скрипт
  `scripts/<задача>.sh` в репозитории и владельцу ОДНА команда
  `cd /opt/astro/app && git pull --ff-only && bash scripts/<задача>.sh`.
  Блоков для вставки в терминал не давать. Меняющий сервер скрипт — только с
  согласия владельца. Сервер руками не редактируем никогда.
- **Деплой запускает Claude Code** (`gh workflow run "CI/CD" --ref main`):
  только из `main`, только при зелёном CI. С 19:00 до 07:00 МСК не деплоить,
  если в выкатываемом диапазоне меняются версии промптов прогнозов. Итог
  (`deploy`, `/health`) шлёт владельцу джоб `notify-deploy`, ждать его не
  нужно. При сбое — прод не чинить.
- **В `main` — только через PR с зелёным CI, прямые пуши запрещены**
  (решение владельца 05.10.2026). Причина: 3bae9b7 (28.09) ушёл в main
  прямым коммитом мимо CI и неделю ронял вкладку транзитов на вебе у всех
  (#123). Срочная правка — тоже PR.
- **APK для приёмки** — владельцу в Telegram (`python notify.py --file`), с
  номером прогона, коммитом и что проверить.
- **Каналов Telegram два:** `notify.py` — личный чат владельца (@claudekrassbot),
  всё серверное — канал @aristeatimesupport. Не путать.
- **Полный `pytest` локально не гонять** (4 ГБ RAM) — точечные тесты, решающий
  прогон в CI. Мобильная задача не «готова» без `npm run build:mobile`.
- **Consistency — один прогон на PR, в конце, после последнего коммита**
  (решение владельца 06.10.2026). Перезапуск — только если раннер не выдан.
  Нужен счётчик, которого нет в логе, — добавить его в скрипт ДО прогона.
- **rtk не ставить** (проверено 06.10.2026, v0.51.0): сжатый вывод pytest
  теряет суть ошибки — тип исключения, внутренний кадр traceback и
  фактические значения assert. Снят полностью — `docs/decisions.md`.

## Важные соглашения

- Не использовать `sudo` с npm
- Framer Motion — только поверх готовых компонентов
- Новые компоненты брать из 21st.dev или Ponytail, не генерировать с нуля
- Один компонент за раз, не рефакторить всё сразу
- Перед правкой файла — уточнить задачу
- Никогда не редактировать файлы напрямую на сервере — только через репозиторий
- Останавливать только свои процессы — по PID, который запустил сам.
  Массово (`taskkill /IM python.exe`, `pkill python` и т. п.) — запрещено:
  на машине владельца работают его собственные процессы (06.10.2026 так
  был остановлен весь Python разом)
- «Готово» означает проверено в работе. Если проверить нельзя (нет браузера,
  Docker, доступа к серверу) — писать «код готов, приёмка не пройдена» и явно
  перечислять, что осталось непроверенным
- Всё, что выясняется по ходу работы, записывать сразу — в этот файл, в
  комментарий или в docstring, туда, где найдёт следующий читающий. Не ждать
  отдельной просьбы и не отдавать владельцу списком «что стоило бы записать».
  Записывать не то, что сделано (это видно из git), а **почему** и **что
  сломается, если сделать иначе**. Особая ценность — у неочевидного:
  намеренные литералы, порядок операций, места, где правильное решение
  выглядит как недоделка. Мысль «выглядит странно, но трогать нельзя,
  потому что…» — это ровно то, что надо записать.

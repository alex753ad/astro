# Спецификация экрана «Лента» — мобильное приложение Aristea Timeline

Версия 1.1, 05.09.2026. Написана после того, как виден настоящий ответ
`GET /api/v1/chart/{chart_id}/feed` на бою (см. `FEED_LIVE_ANALYSIS.md`) —
по правилу из плана сессии: спецификация после ответа ручки, не до.

Источник содержимого — одна ручка `/chart/{id}/feed`. Плюс один запрос
`/profile/charts` при открытии, чтобы выбрать карту (is_primary, иначе
первая; карт нет — состояние «нет карты», §11). Ограничение «одна ручка»
относится к содержимому ленты, не к выбору карты.

Окно запроса фиксированное: `сегодня − 31 день .. сегодня + 334`
(365 дней, ручка отбивает >366). Верхнюю границу по тарифу НЕ считать —
бэкенд сам обрежет, реальный край берётся из `horizon.to` ответа.
«Сегодня» — локальная дата пользователя, не UTC.

Визуальная структура экрана — отдельным документом, `SPEC_FEED_VISUAL.md`.

---

## 1. Решения владельца, на которых стоит эта спецификация

Приняты 05.09.2026, менять только осознанно:

1. **Лунные транзиты сворачиваются** под строку «показать все за день».
   Свёрнутая строка показывает **количество + значки планет**, по которым
   Луна прошла.
2. **Долгосрочные периоды (5 медленных планет) — полосой сверху**, вне
   хронологического потока. В свёрнутом виде: **пять планет со значками и
   домами**, без текста.
3. **Орб и признак точности показываются**, как на вебе («точный» /
   «отходит», орб цифрой).
4. **Заголовок дня липкий** (`position: sticky`).
5. **Лента открывается на сегодня**, прошлое отматывается вверх.

---

## 2. Что отдаёт ручка (факт, не замысел)

Проверено на бою, окно `2026-08-05 .. 2026-12-31`, free, 723 события.

```
{ chart_id, from_date, to_date, timezone, horizon, events[] }
```

`horizon`: `{ from, to, tier, next_tier: { tier, name, to } }` — граница
тарифа и следующий тариф приходят с бэкенда, на клиенте таблицу тарифов
НЕ дублировать.

Событие:

```
key, kind, importance, at, ends_at, duration_days,
locked, text, teaser, started_before, meta
```

Восемь `kind`, распределение на боевой карте за 5 месяцев:

| kind | шт. | Где живёт на экране |
|---|---|---|
| `transit` | 674 (из них 526 лунных) | поток; лунные — под свёрткой |
| `planner_period` | 17 | поток |
| `planner_longterm` | 5 | **полоса сверху**, не в потоке |
| `planner_moon_house` | 4 | поток, под свёрткой лунных |
| `moon_phase` | 10 | поток |
| `eclipse` | 2 | поток |
| `retrograde` | 9 | поток |
| `solar_event` | 2 | поток |

`importance`: `high` 8, `medium` 189, `low` 526. `low` = транзитная Луна.

Всё время — ISO со смещением в таймзоне карты, зона в `timezone`. Никакой
арифметики над временем на клиенте.

## 4. Полоса «сейчас» — долгосрочные периоды

**Что в неё попадает:** все события `kind == "planner_longterm"`. Их всегда
≤ 5 (структурная константа: Юпитер, Сатурн, Уран, Нептун, Плутон — по одному
текущему периоду на планету). Из хронологического потока они **изымаются
полностью**.

**Свёрнутый вид** — горизонтальная полоса из пяти чипов:

```
♃ 11 дом   ♄ 7 дом   ♅ 9 дом   ♆ 6 дом   ♇ 4 дом
```

Значок планеты + номер дома. Без текста: на free все пять `locked: true`,
`theme` пустая, `groups` пустой — текста в данных нет.

**Порядок чипов** — от самого короткого к самому длинному по
`duration_days` (Юпитер → Плутон). Не по `at`: хронология здесь бессмысленна,
периоды идут одновременно.

**Развёрнутый вид** (тап по чипу) — карточка периода:
- планета, дом, тема (`meta.theme`, на free пустая);
- срок: «с ноября 2012 по март 2032», из `at` / `ends_at`;
- при `locked: true` — рекомендации под блюром + кнопка доступа
  (существующий `paywallGate.js`, механика та же, что на вебе).

⚠️ **Высота полосы фиксированная.** Приём «высота ∝ длительности» к ней НЕ
применяется — ради этого долгосрочные и вынесены. Внутри потока после
изъятия ничего длиннее месяца-двух не остаётся, и приём снова честен.

⚠️ **Что потеряно и компенсируется текстом:** привязка к шкале. «Сатурн
выйдет из 7 дома через полгода» на таймлайне больше не видно — эта мысль
должна быть словами в развёрнутой карточке.

## 5. Поток — сортировка и группировка

**Порядок** приходит с бэкенда готовым (`max(at, from_date)`, затем `at`,
затем `key`). Клиент **не пересортировывает**.

**Группировка по дням** — по календарной дате `at` в таймзоне ответа.
Событие, идущее через полночь (`ends_at` в другом дне), принадлежит дню
своего `at`.

⚠️ **`started_before == true`** — период начался до окна. Такие события
бэкенд ставит в начало ленты с клэмпом к `from_date`. Единственный kind,
который это даёт, — `planner_longterm`, а он уходит в полосу сверху.
**Практически в потоке событий с `started_before == true` не остаётся.**
Если появятся (новый kind) — показывать в первом дне окна с пометкой
«началось раньше», дату брать из `at`, а не из позиции.

---

## 6. Заголовок дня

Липкий (`position: sticky`, `top: 0`). Формат: «5 сентября, суббота».
Сегодняшний день — «Сегодня, 5 сентября».

Прилипает, пока идут события своего дня; заголовок следующего дня
выталкивает предыдущий. Высота узкая, одна строка.

Дни без событий не показываются вовсе — пустых заголовков нет.

---

## 7. Свёртка лунных транзитов

**Что сворачивается:** события с `importance == "low"` (это ровно
`transit` с `meta.transit_planet == "Moon"`) плюс `planner_moon_house`.
На боевых данных — 75% всей ленты, 4–5 записей в день.

**Свёрнутая строка** внизу блока дня:

```
· ещё 5 лунных   ☉ ☿ ♀ ♄ ♃ ·
```

Количество + значки **натальных точек**, по которым Луна прошла
(`meta.natal_planet`), без повторов. Не значки Луны — она в каждом
событии одна и та же, информации в ней нет.

Тап разворачивает список внутри дня, повторный — сворачивает. Состояние
не запоминается между днями и не персистится.

**Фазы Луны и затмения (`moon_phase`, `eclipse`) под свёртку НЕ попадают** —
у них `importance` `medium`/`high`, это события, а не фон.

⚠️ **Затмение поглощает свою фазу** (сделано на бэкенде 05.09.2026): солнечное
бывает только в новолуние, лунное — только в полнолуние, поэтому фаза, совпавшая
с затмением по времени, в ленту не приходит вовсе, а её знак зодиака переезжает
в `meta.sign` затмения. Клиенту делать ничего не нужно — просто знать, что в
месяце с затмением соответствующей фазы в данных не будет.

## 8. Карточка события в потоке

Высота блока пропорциональна `duration_days`. У событий-точек
(`ends_at == null`: транзит, фаза, затмение, ретроградная станция,
равноденствие) длительности нет — они рисуются точкой фиксированной высоты.
Пропорция применяется только к `planner_period` (и то, что придёт с
`ends_at`).

Содержимое:

| Элемент | Источник | Примечание |
|---|---|---|
| Время | `at` | «14:43», день уже в заголовке |
| Заголовок | `text` | сейчас «Меркурий Оппозиция Сатурн» |
| Знаки | `meta.transit_sign` → `meta.natal_sign` | «13.3° Лев → Телец» |
| Признак точности | `meta.applying` | `true` → «точный», `false` → «отходит» |
| Орб | `meta.peak_orb` | «орб 0.1°», округление до 0.1 |
| Тизер | `teaser.intro` / `teaser.outro` | только если `teaser != null` |
| Действие | `locked` / `teaser` | «Интерпретация» или «Открыть доступ» |

⚠️ **Шаблонных текстов не будет — решение владельца 05.09.2026.** Если
шаблон объясняет каждый транзит, платный ИИ-разбор покупать незачем: человек
пролистает ленту, увидит осмысленную фразу на каждой строке и решит, что уже
получил всё. Карточка показывает **фактуру** — планеты, аспект, знаки, орб,
точность. Смысл платный.

Поэтому 28 заготовок отменены, `templates.json` остаётся только под тизер.
Читаемость `text` достигается формой, а не словами: значки планет вместо
названий, аспект цветом (см. `SPEC_FEED_VISUAL.md` §4).

⚠️ **`teaser != null` — единственный признак «закрыто» для транзита.**
Не выводить это из тарифа на клиенте: бэкенд уже учёл `free_unlocked`
(топ-2 значимых транзита открыты на free).

---

## 9. Край горизонта

Последним элементом ленты, после событий последнего дня:

> Дальше — транзиты и периоды до 31 марта. Открывается на Веге.

Дата — `horizon.next_tier.to`, название тарифа — `horizon.next_tier.name`.
Оба с бэкенда. Если `next_tier == null` (premium) — карточки нет.

За `horizon.to` не показывается **ничего**, включая лунные: решение сессии,
иначе за краем остаются одинокие значки и это выглядит поломкой, а не
границей тарифа.

Полный лунный календарь без ограничений — отдельный месячный вид, не здесь.

---

## 10. Открытие экрана

Лента открывается **на сегодня**: первый видимый заголовок — сегодняшний
день. Прошлое (ровно месяц, одинаково на всех тарифах) отматывается вверх.

Реализация: якорь на заголовок сегодняшнего дня, прокрутка к нему без
анимации до первого кадра. Если событий сегодня нет — якорь на ближайший
следующий день с событиями.

---

## 11. Состояния

| Состояние | Что показываем |
|---|---|
| Загрузка | скелет: полоса сверху + 3 карточки |
| Ошибка сети | «Не удалось загрузить ленту», кнопка «Повторить» |
| Нет карты у аккаунта | экран создания карты, ленты нет |
| Лента пуста (0 событий) | не наблюдалось на бою; текст-заглушка |

⚠️ Ошибка `Chart not found: <uuid>` показывает пользователю внутренний
идентификатор — известный долг из сессии 04.09.2026. На этом экране
перехватывать и показывать человеческий текст.

## 12. Открытые вопросы — до реализации

1. ✅ **Дубль затмения и новолуния — закрыт** 05.09.2026 на бэкенде,
   см. §7. Заодно выяснилось, что транзит «Луна Соединение Солнце» —
   не новолуние, а Луна над **натальным** Солнцем; к дублю отношения не
   имеет и под свёрткой лежит правильно.
2. ✅ **Потолок высоты `planner_period` — не нужен.** Закрытые периоды
   заполняются витриной под блюром; витрина не добавляет своей высоты
   (`flex: 1` + `overflow: hidden`), иначе двухдневный проход Луны стал бы
   выше тридцатидневного периода Солнца.
3. ✅ **Чипы помещаются** — пять штук в 390 px без прокрутки, замерено.
4. ✅ **Заготовки отменены** — см. §8.
5. ⏳ **Бесконечный скелет при повторном запуске APK.** Первый запуск
   работает, повторный висит. Открыто, разбирается.

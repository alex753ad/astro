# Правила мобильного приложения

Вынесено из корневого CLAUDE.md 27.09.2026. Правка меняет правило — этот файл правится в том же коммите.

### Приёмка на боевом API проверяет пару «новый APK + СТАРЫЙ сервер»

Записано после 16.09.2026, когда два дефекта приёмки оказались одним и тем же.
Время прохода Луны расходилось с вебом ровно на пояс, а прошедший проход
приходил без расшифровки — оба уже были исправлены в коде, но ветка не
деплоилась, и приложение говорило с прод-бэкендом прошлой недели.

⚠️ **Это не видно ниоткуда.** APK свежий, фронтенд новый, ошибок нет; сервер
отвечает исправно — просто старым кодом. Разбор при этом уходит в тот код,
который у тебя перед глазами и который уже правильный.

**Правило: перед разбором любого расхождения, замеченного НА УСТРОЙСТВЕ,
сначала проверить, доехал ли бэкенд.** Дешевле всего — по публичному следу
свежей правки (строка на `/pricing`, поле в открытой ручке). И отдельно:
мобильная приёмка на боевом API имеет смысл только после деплоя ветки, иначе
проверяется пара, которой не будет существовать.

⚠️ Истину о расчёте при этом всё равно нельзя брать ни с одного из двух
экранов — только прямым счётом мимо обоих (разбор — «Проход Луны по дому
отдавался со сдвигом времени на пояс» ниже).

## Мобильное приложение — две вещи, которые ломаются молча и НЕ видны на десктопе

Обе найдены 05.09.2026 при сборке экрана «Лента» (`frontend/src/mobile/`).
Общее у них то, что на машине разработчика всё выглядит правильно, а
ломается на телефоне — то есть обычная проверка «посмотрел, работает» их
не ловит.

### Палитра — источник истины не здесь

Значения токенов — `frontend/src/mobile/mobile.css` (`:root`/`.dark`). Какая
тема по умолчанию и почему — `DESIGN_SYSTEM.md` §1 и запись v1.3 в его
changelog (умолчание в мобильном приложении обратное вебу: светлая
основная). Третьего описания здесь нарочно нет — за цветом в прототип
(`aristea-mobile.html`) тоже не ходить, он не источник истины.

### Астрологические значки требуют своего шрифта, системного не хватает

Значки планет и точек (♃ ♄ ♅ ♆ ♇ ☉ ☽ ☿ ♀ ♂ ☊ ☋, блок Unicode Misc
Symbols) нельзя рисовать системным шрифтом. На Android и iOS покрытие
этого блока либо ОТСУТСТВУЕТ — и вместо значка встаёт пустой прямоугольник
(тофу), — либо подменяется цветным emoji-шрифтом, который рисует картинку и
**игнорирует `color`**: значок перестаёт слушаться темы и на тёмном фоне
остаётся тёмным.

**На десктопе этого не видно вообще.** В Windows и macOS системные шрифты
эти кодпоинты покрывают, поэтому и в браузере разработчика, и на
скриншотах всё правильно; расходится только на устройстве.

Лечение уже лежит в репозитории и его не нужно изобретать заново: сабсеты
`src/assets/fonts/NotoSansSymbols-subset.woff2` (всё, кроме Солнца) и
`NotoSansSymbols2-subset.woff2` (только ☉ U+2609 — в первом файле его нет,
это свойство шрифтов Noto). Веб подключает их внутри `NatalChart.jsx`,
мобильное приложение — через `@font-face` семейства `AstroSymbols` в
`mobile/mobile.css`; потребители берут его из `mobile/lib/feedGlyphs.js`.
Файлы общие, третьей копии заводить не нужно.

История: Прокрутка к якорю сбивается подменой шрифта (лента открывается не на сегодняшнем дне) — [docs/HISTORY-mobile.md](../../../docs/HISTORY-mobile.md).

История: Холодный старт и задерживающий лимит nginx на `/api/v1/auth/` (гейт по сроку токена, `REFRESH_COOLDOWN_MS`) — [docs/HISTORY-mobile.md](../../../docs/HISTORY-mobile.md).

История: Обновление сессии: одноразовая цепочка таймера, `delay <= 0`, разбор по размеру ответа в логах nginx — [docs/HISTORY-mobile.md](../../../docs/HISTORY-mobile.md).

### Объект плагина Capacitor нельзя возвращать из async-функции и нельзя await-ить

**`Preferences` — не объект, а `Proxy`** (`registerPlugin`,
`@capacitor/core/dist/index.js:157-172`). Его `get`-ловушка отдаёт вызов
моста для ЛЮБОГО имени свойства; исключений ровно четыре: `$$typeof`,
`toJSON`, `addListener`, `removeListener`. **Имени `then` среди них нет** —
значит по правилам языка этот Proxy является thenable.

Дальше работает механика промисов, а не Capacitor: `return Preferences` из
`async`-функции (равно как и `await Preferences`) пропускает значение через
разворачивание thenable, то есть **вызывает `Preferences.then(resolve,
reject)`**. Мост принимает `then` за имя метода плагина и отвечает
`"Preferences.then()" is not implemented on android`, а `resolve` и `reject`
считает аргументами вызова и **не вызывает никогда**.

⚠️ **Поэтому это не ошибка, а зависание, и оно проходит мимо всех
предохранителей сразу.** Промис не разрешается и не отклоняется:
- `catch` вокруг `await` не срабатывает — отклонения нет;
- `finally` не срабатывает — промис не завершается, а `finally` выполняется
  только на завершении. Значит и `refreshInFlight` (`api/client.js`) остаётся
  заполненным НАВСЕГДА: каждый следующий `refreshSession()` получает по
  ранней ветке тот же неразрешающийся промис, и все четыре пути обновления
  (таймер, возврат из фона, монтирование, 401) молчат разом, по одной
  причине;
- отказ уходит в промис, который никто не слушает, — единственный внешний
  признак это `Uncaught (in promise)` в консоли `chrome://inspect`.

**Правило: объект плагина Capacitor никогда не возвращать и не `await`-ить
напрямую.** Только обёртку (`return { plugin: mod.Preferences }`) либо
результат конкретного метода (`await Preferences.get({...})` — здесь под
`await` уже промис метода, а не Proxy). Это касается любого плагина, не
только Preferences: свойство общее для всего `registerPlugin`.

История: Разбор этого дефекта целиком (цена, ошибочно приписанное следствие, порядок веток `register`/`session-diag`, методологический вывод про «подтверждено измерениями») — [docs/HISTORY-mobile.md](../../../docs/HISTORY-mobile.md).

Инвариант закреплён тестом `frontend/src/api/authTransport.test.js`:
свойство `then` у объекта плагина не читается никогда. Мост подделан тем же
`Proxy`, что и настоящий, зависание ловится гонкой с таймером и читается как
`ПОВИСЛО`, а не как таймаут прогона; DOM-окружение не нужно — дефект чисто в
механике промисов. Проверено обратным прогоном на коде ДО правки: падают все
четыре кейса. Существующий `session.test.js` поймать это не мог по
построению — он подменяет весь модуль транспорта заглушкой, у которой нет
`then`.

История: Тариф не доезжал до приложения: `onTokensRefreshed` без подписчиков, `lib/sessionUser.js` — [docs/HISTORY-mobile.md](../../../docs/HISTORY-mobile.md).

### ⚠️ CI не собирает мобильный бандл — поломку импорта в `src/mobile/` он не видит

Найдено 13.09.2026 на своей же правке: удалил функцию из
`localNotifications.js`, забыл импорт в `MoreNotificationsView.jsx`, и **все 424
теста остались зелёными**, веб-сборка тоже — потому что `MoreNotificationsView`
в веб-граф не входит вовсе, а vitest грузит только те модули, что тянут тесты.

Job `test-frontend` в `ci.yml` делает `npm test` и `npm run build` — **веб**.
Мобильный вход (`npm run build:mobile`) собирается только в workflow
`Mobile APK`, а он ходит по требованию и на пуш в ветку `mobile`.

Практически: поломка такого рода доезжает до первой сборки APK, то есть до
приёмки — на прод она уехать не может, потому что мобильного кода на проде нет.
Но «CI зелёный» про мобильную часть не означает «собирается». Перед тем как
говорить «готово» по мобильной задаче — гонять `npm run build:mobile` локально
или дожидаться APK, а не CI.

## Шаг 4 аудита под флагом sky_event: решения 4.6–4.8 (06.10.2026)

- **`peak_date` — UTC-дата касания, только ключ; `touch_date` — местная, для
  экрана** (владелец, 4.8). Ключ должен быть одним в любом поясе: на нём
  держатся кэш разбора (`find_event` ищет касание ±1 день от него), ссылка
  письма «Важный транзит» (`event={UTC-дата}-…`) и `eventKey` веба. Показ —
  по местной дате, иначе во Владивостоке касание после полуночи стояло бы
  вчерашним. Веб: `TransitTimeline.dayOf`; поле — `schemas.TransitEvent.touch_date`.
- **Точки — `day_event.points` во всех разделах** (лента, разбор, чат, PDF,
  `/transits`): с ASC и MC, без Юж. узла, к узлам — только соединение и
  оппозиция; без времени рождения — без Луны, ASC, MC (c8). Один набор — одни
  события везде; на вебе с 4.8 под флагом появились ASC/MC и ушли Юж. узел и
  квадраты к узлам.
- **Прогрев ядра — вариант В** (владелец, 4.8): три месяца — ежечасно для
  всех карт под флагом; год вперёд — фоновой задачей `tasks.sky_warm_year`
  при первом открытии вкладки транзитов на вебе в месяце; дальше года —
  месяц в запросе (≈1 с). TTL чанка — не раньше конца его года. Почему не
  «год всем»: год на карте — ≈1,43 МБ в Redis и ≈16 с CPU, а дальние месяцы
  нужны только тем, кто листает веб. Память при флаге «всем» — открытый
  вопрос (замер сжатия — handoff).
- **Чат под флагом — события, у которых сегодня проход в орбе** (4.6): в
  перерыве петли событие не «активно» — так же, как без флага (движок на
  один день его не видел).

## CRM под флагом sky_event: 4.12 (06.10.2026)

- **Узлы в CRM — как в ядре** (владелец, 06.10.2026): Северный узел, к нему
  только соединение и оппозиция; Юж. узла нет. Раньше CRM брала
  `chart.planets` с Юж. узлом и всеми аспектами к узлам — это была часть
  «точка/аспект» в разбивке Consistency (cB CRM 86). Своего набора точек у
  CRM нет: иначе астролог видел бы у клиента не те события, что сам клиент
  в приложении.
- **Флаг — по астрологу** (`crm.crm_sky`), а не по клиенту: CRM видит
  астролог, у карты клиента нет человека приложения.
- **Пояс — `NatalChart.timezone` клиента**, «сегодня» — местный день клиента;
  в списках по нескольким клиентам у каждой строки свой пояс, групповой
  прогноз упорядочен по моменту касания (UTC) — местные даты разных поясов
  не сравнимы.
- **Строка — касание**, станция без касания — без строки; письмо и бриф — на
  событие, касания и срок словами `touches_ru` / `period_ru`, в брифе без «~».

## Чанки ядра — zlib, TTL до конца года, без скользящего TTL (06.10.2026)

Решение владельца по замеру на вымышленной карте (год — 13 чанков, 1986
событий): JSON 1,43 МБ; zlib 112 КБ; только поля веба 693 КБ; оба 64 КБ.
Выбран zlib всего чанка (`sky._pack`, ключ `sky:v2`): чанк общий для ленты,
чата, разбора, PDF и веба — урезать поля значило бы завести второй кэш. В
Redis строка base64 (RedisCache хранит строки) — ≈150 КБ на год карты,
≈150 МБ на 1000 карт. Чтение года из кэша не замедлилось: разбор 13 чанков
0,088 → 0,068 с (локально, без сети). TTL — до конца года чанка (не раньше
конца следующего месяца); скользящий TTL «30 дней после просмотра» не взят:
продление на каждое чтение и ≈16 с CPU на повторный прогрев после паузы.

## Год в перерывах петли — отдельно от срока (06.10.2026)

Год — у последней даты каждого года, но в сроке и в перерывах по отдельности, и год конца события в перерывах не пишется: «1 ноября 2026 — 18 июля 2027, с перерывом с 24 декабря 2026 по 26 июня» (по всей строке сразу начало вышло бы «1 ноября» без года и читалось бы как 2027). Одна функция для разбора, чата и PDF — `transit/prompts.period_ru` / `gaps_ru`.

## rtk проверен и снят 06.10.2026

rtk v0.51.0 (github.com/rtk-ai/rtk, сборка `x86_64-pc-windows-msvc`, сумма
сверена с `checksums.txt`) ставился хуком PreToolUse на Bash (`rtk init -g`:
хук `rtk hook claude` в `~/.claude/settings.json`, `~/.claude/RTK.md` и
`@RTK.md` в `~/.claude/CLAUDE.md`). Хук переписывает `git …`, `python -m
pytest`, `gh …` в `rtk …`; команду с путём к `.venv` и составные — нет.

Проверка на заведомо падающих тестах: имя теста, файл:строка и строка assert
видны; **пропадают** фактические значения (`assert '2027-06-28' ==
'2027-06-29'` и дифф), тип исключения (`IndexError: …`), внутренний кадр и
локальные переменные (`s = '2027/06/29'`) — остаётся ссылка `rtk recall`.
`git diff` — полный. Лог упавшего `gh run --log-failed` — не сжат вовсе.
Ошибка теряется → по условию владельца снят: `rtk init -g --uninstall`,
`settings.json` возвращён из копии до установки (uninstall оставлял пустой
`"hooks"`), бинарник и каталоги данных rtk в AppData (история выводов)
удалены.

⚠️ Если ставить снова: хук зовёт `rtk` по имени, а PATH оболочки Bash
снимается при старте сессии — после `init` каждая `git` сразу падала с
`rtk: command not found`, пока бинарник не лёг в каталог, уже бывший в PATH.

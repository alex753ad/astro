# Флаги функций

Режим до публикации (CLAUDE.md, п.9): новая функция — только за флагом,
выключенным на проде до слова владельца. Исправления ошибок — без флага.

## Как устроено

* Список ключей — `FLAGS` в `backend/flags.py` (ключ → что включает). Ключ
  не из списка: `flag_on` падает, строка в БД игнорируется.
* Режим — таблица `feature_flags` (069): `off` / `all` (и гостям) / `users`
  (только перечисленные аккаунты). Нет строки — выключен.
* Включает владелец: `/admin` → «Флаги», почты через запятую. Каждая запись —
  строка `set_flag` в `admin_audit_log`. Скрипта нет намеренно (решение
  владельца 30.09.2026): админка видна с телефона и показывает состояние.
* Сервер: `flag_on(db, key, user)`; кэш в процессе 30 с.
* Клиент: `GET /api/v1/flags` (гость или вход) → `{"flags": [...]}`; то же
  поле `flags` в `/auth/me`. Сайт и приложение — `useFlag('key')` из
  `frontend/src/lib/flags.js`: запрос при первом useFlag, смене аккаунта и
  возврате на вкладку/в приложение, не чаще раза в 30 с. Включение доходит
  до минуты без деплоя и без нового APK. Пока ответа нет — выключено.

## Правило для задания с новой функцией

1. Имя: `область_что`, латиницей, snake_case — `feed_week_view`, `chat_voice`.
2. Ключ и описание — в `FLAGS`; строка в таблицу «Живые флаги» ниже.
3. Проверки в коде:
   * ручки функции — `if not flag_on(db, KEY, user): raise HTTPException(404)`;
   * экран/кнопка — `useFlag(KEY)`; выключено — не рендерится;
   * пуши и письма — `flag_on` на каждого получателя ДО отправки и до
     записи в `push_sent_log` / `email_sent_log`.
4. Тест в файле функции, флаг выключен (по умолчанию так и есть):
   ручка отвечает 404, ключа нет в `/api/v1/flags`, прогон рассылки/тика не
   создаёт строк в `push_sent_log` и `email_sent_log` и не зовёт отправку.
   Общий тест `backend/tests/test_feature_flags.py` ловит ключи в
   `flag_on(...)` / `useFlag('...')`, которых нет в `FLAGS`.
5. Владелец сказал «включаем навсегда» — отдельным заданием убрать проверки
   и ключ из `FLAGS`, строку отсюда перенести в «Снятые».

## Что уже выяснено

* **История «Луны по домам» (раздел 1).** Прошлое в ленте — ровно месяц
  от сегодняшнего дня, одинаково для всех тарифов: сервер
  `backend/feed/horizon.py` `PAST_MONTHS = 1`, приложение
  `frontend/src/mobile/lib/feedApi.js` `PAST_DAYS = 31`. От регистрации
  не зависит, фиксированной даты нет. Свежая фикстура (28.09): лента с
  2026-08-28, проходы Луны — с 2026-08-27. «Начало августа» у владельца —
  вероятно, старый APK или веб-планер (у веб-планера свой просмотр недель
  по месяцам — не проверено).
* **Раздел 3 — предположение, не проверено.** Окно счётчика
  (`rate_limits.usage_window`) выбирается по активной подписке, а лимит —
  по `TIER_FLAGS[user.tier]`. После покупки ключ счётчика сразу
  становится ключом оплаченного окна (новый якорь), поэтому бесплатный
  PDF этого месяца не должен переноситься. Нужен тест free → lite и
  free → pro через `activate_subscription` (образец —
  `backend/tests/test_usage_paid_period.py`).
* **Раздел 5.** Отдельного ежедневного сообщения в коде нет —
  `selfcheck.run_daily` шлёт только сигналы и «починилось». Тесты
  `test_selfcheck.py` (`test_daily_run_twice_signals_once`,
  `test_daily_run_signals_dislikes`) проверяют число сообщений — их
  придётся поменять вместе с правкой. Число родовых форм уже есть в
  `stats.summarize()["gendered_you"]`.
* **Раздел 6.** PDF сейчас берёт последний сохранённый разбор без учёта
  тарифа (`main.py`, `start_pdf_generation`); у `interpretations` нет
  колонки тарифа — нужна миграция 067. Скрипт
  `scripts/regen_interpretation_80605fbf.sh` пока тариф не пишет.
  Смета из одобренного плана: Лира ≈1,2–2,4 ₽ за PDF при готовом разборе,
  до ≈5 ₽ в худшем случае; Вега ≈1–2 ₽.

  (миграция 066).

  главные пункты — `OFFER_MAIN` в `lib/tierCatalog.js`.

  при показе (`PlannerPage.datesInWords`) — строка с сервера уходит и в
  промпт.

  `docs/planner_texts_review.md` (часть правок владелец уже поменял в

# История: аудит безопасности

Вынесено из `CLAUDE.md` 13.09.2026. Текст перенесён дословно.

### Проверено и держится — перепроверять не нужно

- **Сумма чекаута клиентом не управляется.** `CheckoutRequest` объявлен с
  `extra: "ignore"`, цена берётся только из `TIER_PRICES_RUB[tier]`,
  `return_url` всегда свой, `premium` отбивается явным 400.
- **Тариф и сумма в вебхуке берутся из перечитанного платежа**
  (`GET /v3/payments/{id}`), а не из тела уведомления. Подделанное тело даёт
  либо 403, либо запрос несуществующего платежа → отказ без активации.
- **Идемпотентность — на уникальном индексе `payment_events.inv_id` в БД**
  (не в Redis: там она была fail-open). Запись платежа и активация — одна
  транзакция, при падении активации общий rollback.
- **`client_ip` fail-closed** (`limiter.py`): `X-Forwarded-For` разбирается
  справа налево до первого недоверенного адреса, при пустом
  `TRUSTED_PROXY_IPS` заголовок игнорируется целиком. Подделать левые
  сегменты бесполезно.
- **BOLA по картам закрыт**: `resolve_chart_access` (`main.py`) — везде 404,
  `secrets.compare_digest` для `access_token`, проверка `expires_at`.
  Используется во всех эндпоинтах с `chart_id`. Идентификаторы — UUID.
- **CRM изолирована**: все ручки с `client_id` идут через
  `_get_client_or_404`, где стоит `ClientProfile.astrologer_id ==
  astrologer.id`. Чужого клиента не получить.
- **SSE-тикеты одноразовые**: атомарный `GETDEL`, TTL 60 с, fail-closed при
  недоступном Redis.
- **`token_version` гасит все токены разом**: смена пароля и `logout-all`
  инкрементят счётчик, и это обесценивает access, refresh, ссылку сброса
  пароля и ссылку подтверждения email одновременно. Алгоритм JWT берётся из
  настроек, не из токена (`alg: none` невозможен).

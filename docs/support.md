# Поддержка: лист в приложении, канал в Telegram

Вынесено из корневого CLAUDE.md 27.09.2026. Правка меняет правило — этот файл правится в том же коммите.

### Поддержка в приложении — один лист, канал `POST /feedback` → Telegram (27.09.2026)

Лист `mobile/components/SupportSheet.jsx`, открывается `openSupport({screen,
error})` (`lib/supportBus.js`) из меню «Ещё», с листа оплаты, из «Оплата и
поддержка» и ссылкой `SupportLink` под каждым сообщением об ошибке. Ответ — на
почту аккаунта; внешних ссылок (mailto, t.me) нет — решение владельца.

* Уходит: версия (`__APP_RELEASE__`, с хешем), модель из user-agent (без
  плагина; урезанный UA даёт только «Android N», модель не выдумывается),
  номер аккаунта, текст ошибки. Значения человеку НЕ показываются с 27.09.2026
  (решение владельца) — только фраза «уйдут версия приложения, модель телефона
  и номер аккаунта — так быстрее разберёмся». Email виден открыто («Ответим на
  почту …»); в сигнал его и номер аккаунта сервер берёт из токена, не из формы.
* ⚠️ Текст ошибки чистит `scrubErrorText` (`lib/supportContext.js`): email тем
  же выражением, что Sentry, плюс даты, время, год, координаты и всё в
  кавычках (так сервер цитирует место рождения).
* Черновик в localStorage переживает закрытие листа и отказ сети.
* Лимит `5/hour` на `POST /feedback` (общий с жалобами веба): вошедший — по
  user_id из ПОДПИСАННОГО токена, аноним — по IP (`feedback_key`). ⚠️ Не
  `_base_id`: ручка открыта без входа, и ключ по строке токена давал бы новое
  ведро на каждый мусорный заголовок.
* ⚠️ **Токен бота — часть пути запроса** (`/bot<токен>/sendMessage`), а httpx
  на INFO пишет каждый запрос с полным URL: 27.09.2026 токен стоял в
  `docker compose logs api` и попал в вывод диагностики. Уровень httpx поднят
  до WARNING в `notifications/telegram.py` (этим модулем шлют api, worker и
  beat), хлебные крошки Sentry режут `/bot…` (`sentry_setup._strip_query`).
  Успешная отправка пишет `доставлено в чат …, message_id=…` — «не дошло»
  проверяется по этой строке, а не по «200 OK».
* ⚠️ **С сервера api.telegram.org открыт только по IPv6** (30.09.2026,
  `scripts/check_telegram.sh`). Клиентов к Telegram два, и оба привязаны к
  IPv6 по-своему: сигналы — httpx в `notifications/telegram.py`
  (`local_address="::"`), бот в контейнере `bot` — aiohttp внутри aiogram
  (`bot/pilot_bot.py`, `_session`, `family=AF_INET6`). Правка одного другой
  не касается. Оба повторяют запрос через 5 и 30 с, только если соединение
  не установилось. Проверка бота — шаги 6–8 `scripts/check_support_bot.sh`.
* Версия, телефон и ошибка лежат в `feedback.context` (JSON, миграция 060) и
  видны в админке. Запись в БД — ДО Telegram; недоставленный сигнал —
  `logger.error`, то есть событие в Sentry, а не тихая потеря.

### Веб: плавающая кнопка и /pricing (28.09.2026)

`components/FeedbackButton.jsx` — одна на весь сайт, кроме экранов из
`HIDDEN_ON` (сейчас `/pricing`: круг перекрывал кнопку последней карточки).
Там под «Как получить доступ» строка «Вопрос по оплате? Написать в поддержку»:
`openFeedback('payment')` открывает ту же форму, `screen=payment` — сервер
приложит контекст оплаты (`PAYMENT_SCREEN`), как из истории платежей.

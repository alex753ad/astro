# Виджет Android «День» — отчёт и план (флаг `widget`)

**Решения владельца 02.10.2026:** свой нативный плагин и запас на 14 дней —
да; размеры 4×1 и 2×2, без 2×1; время события на виджете оставляем. Тексты
дней без события — `docs/widget_phase_texts.md`.

02.10.2026. На согласовании, кода нет. Наброски (`widget-sketches.png`, `widget.html`) в main не перенесены —
остались в истории удалённой ветки `wip/tariffs-pdf` (решение владельца 06.10.2026).

## 1. Как сделать на Capacitor

- Виджет главного экрана в Android — только нативный: `AppWidgetProvider` +
  `RemoteViews` (Kotlin + XML-разметка). WebView и React внутри виджета не
  работают, переиспользовать экран ленты нельзя.
- Готового плагина нет: официального у Capacitor нет; из сторонних
  (`capacitor-widgetsbridge-plugin` и подобные) — в основном под iOS,
  на Android дают лишь «записать строку и обновить виджет», остальное всё равно
  пишем сами. Брать зависимость ради 20 строк не предлагаю.
- ⚠️ Каталог `frontend/android/` не в git — CI создаёт его каждым прогоном
  (`scripts/patch-android.mjs`). Поэтому код виджета — **локальный плагин**
  в репозитории (`frontend/plugins/widget/`, подключается `file:` в
  package.json); `cap sync` сам вносит его Kotlin, разметку и `<receiver>` в
  манифест. Патчер не трогаем.
- Пишем сами (оценка ~400 строк Kotlin/XML + ~60 JS):
  - `DayWidgetProvider` — рисует из сохранённых данных, выбирает разметку по
    размеру;
  - будильник на местную полночь (`AlarmManager`, неточный — новых разрешений
    не нужно) + перестройка после перезагрузки, смены времени и пояса;
  - мост для JS: `save(days)`, `clear()`, `setEnabled(bool)`;
  - 8 картинок фаз Луны (векторные, в палитре);
  - 3 разметки: 4×1, 2×2, 2×1.
- По правилу docs/mobile.md («нативный плагин — отдельным решением
  владельца»): **что даёт** — приложение на главном экране, существующими
  средствами не закрывается; **чего стоит** — нативный код в репозитории,
  пересборка APK, новых разрешений нет, сторонних библиотек нет.

## 2. Данные и обновление

Предлагаю: **приложение само кладёт виджету запас на 14 дней вперёд**, виджет
в сеть не ходит.

- Новая ручка `GET /api/v1/widget` — по каждому из 14 дней: дата, фаза Луны
  (ключ, как в `story_card.PHASES`), главное событие через
  `day_event.main_event` (заголовок `title()` — «15:01 · Луна к твоей
  Венере», совет `advice()`). Своего отбора нет — так требует докстринг
  `day_event.py`: пуш и виджет обязаны говорить одно.
- Приложение запрашивает её при открытии и возврате из фона (раз в несколько
  часов) и пишет в SharedPreferences через плагин.
- Без входа в приложение и без интернета — виджет показывает свой день из
  запаса. Смена дня — в местную полночь телефона по будильнику.
- Запас кончился (14 дней не открывали) — фаза Луны считается на телефоне
  (простая формула, верна всегда), вместо события «Открой Аристею, чтобы
  обновить день».
- **Почему не сам виджет ходит на сервер.** Нужен токен, а refresh у нас
  одноразовый: виджет, обновивший сессию в фоне, выбивает приложение из
  аккаунта. Дублировать логику обновления сессии в Kotlin — та же ошибка
  дважды. Пуш с данными в закрытое приложение потребовал бы своего
  Firebase-сервиса — дороже, а выигрыш — только свежесть позже 14 дней.
- Выход из аккаунта — запас стирается (там же, где `offlineCache`), виджет
  показывает «Войди, чтобы видеть свой день».
- Оговорка: день события считается в поясе аккаунта (как у пуша), виджет
  выбирает строку по дате телефона. В поездке со сменой пояса возможен сдвиг
  на сутки в районе полуночи — предлагаю принять.

## 3. Что показать и размеры

- Фаза Луны картинкой (8 фаз), дата и название фазы, событие со временем,
  совет из пуша (до 60 знаков, уже согласованы).
- День без события — название фазы и совет фазы (тексты дам таблицей; фразы
  из карточки для сторис — от первого лица, сюда не подходят).
- Размеры — **один виджет, растягиваемый**, три разметки:
  - **4×1 — основной**: Луна · дата и фаза · событие · совет в строку;
  - **2×2**: Луна, событие в две строки, совет;
  - **2×1**: Луна, время, событие — без совета (не помещается).
  В списке виджетов — одна позиция «Аристея · День».

## 4. Нажатие

Открывает приложение. Лента и так открывается на сегодняшнем дне —
отдельного перехода не нужно (`@capacitor/app` для ссылок не ставим).
Если хотите сразу на прогноз дня — скажите, это один параметр запуска в плагине.

## 5. Флаг `widget`

- В манифесте виджет **выключен по умолчанию** — в списке виджетов его нет.
- Приложение после `/flags`: флаг включён — `setEnabled(true)`, виджет
  появляется в списке; выключен — стирает запас и `setEnabled(false)`.
- ⚠️ Флаг доходит до виджета только при открытии приложения: другого канала с
  сервера у виджета нет. Выключили флаг — у человека виджет пропадёт, когда он
  откроет приложение. Отключённый компонент лаунчер убирает с экрана (на
  части лаунчеров — плашка «Виджет недоступен»).
- Ручка `/widget` тоже проверяет флаг (403 без него) — запас не придёт.

## 6. Оформление

Палитра «атлас» из `storyCard.js` (`ATLAS`): фон `#0F1A33`, золото
`#D9B56A`, текст `#F3E9D2`, приглушённый `#AFA58F`, литера «A» `#B9A0F5`.
Literata для события, Golos Text для остального. Всегда тёмный, в любой
теме телефона. Наброски — см. начало файла.

## 7. Что нужно от вас

1. «Да» на нативный плагин (п. 1) и на схему «запас на 14 дней» (п. 2).
2. Размеры: все три или только 4×1 + 2×2.
3. Тексты для дней без события — таблицей (8 фаз), пришлю после «да».
4. Время события на главном экране — оставляем (экран видят посторонние;
   на карточке для сторис время убрали).
5. Проверка на 2–3 телефонах разных марок (Samsung, Xiaomi, любой «чистый»
   Android): Xiaomi и часть Huawei режут фоновые будильники — смену дня в
   полночь проверить можно только на устройстве. Что смотреть пришлю списком
   вместе с APK.
6. Флаг `widget` на себя в /admin → «Флаги» перед приёмкой.

## План работ (после «да»)

1. Бэкенд: флаг `widget` в `FLAGS`, ручка `/widget` (`asyncio.to_thread`),
   тест на совпадение с `main_event` и на 403 без флага.
2. Локальный плагин `frontend/plugins/widget`: провайдер, разметки, фазы,
   будильник, мост.
3. Приложение: `lib/widgetSync.js` — запрос, запись, флаг, стирание при
   выходе; тест на thenable-Proxy плагина.
4. `npm run build:mobile`, APK из CI → вам в Telegram с чек-листом.
5. Правило — в docs/mobile.md, «Виджет».

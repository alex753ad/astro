## Исходный план (06.10.2026)

- **Где события неба** (все — `calculate_transits` по сырому `chart.planets`, без кэша, без ядра и флага):
  дашборд «Важные периоды» `GET /crm/alerts` (7 дней, медленные к личным, `exact_date` = `peak_date`);
  «Пора напомнить» `/crm/reactivation` (21 день, первая причина без даты); групповой прогноз `POST /crm/group-forecast` (до 90 дней, дата = `peak_date`);
  ежемесячное письмо клиентам `_month_transits` + `send_client_broadcast_task` (30 дней, без фильтров, «Planet aspect Natal · YYYY-MM-DD»);
  бриф к встрече `POST /clients/{id}/brief` (30 дней, в промпт «точно ~{exact_date}»). Карточка клиента — общий `TransitTimeline` → `GET /transits` (4.8 уже). `GET /clients/{id}/transits` — без вызывающих. Портал — без транзитов.
- **Расходится с ядром:** «точная дата» — минимум орба на сетке (`peak_date`), а не корень; станции не отбрасываются (`no_touch` не фильтруется) — «точно» в день разворота; окно режет события, петля — проходами; точки — `chart.planets`: с Юж. узлом, без ASC/MC, у карты без времени — с Луной (как c8 до шага 3); `MAX_ORB = 3.0` ничего не режет; «сегодня» — `date.today()` сервера (UTC), даты — UTC.
- **Пояс:** у клиента поля пояса нет; предложение — пояс карты клиента (`NatalChart.timezone`, через `user_tz(None, None, chart)`), «сегодня» и даты — в нём. В дашборде по нескольким клиентам — у каждой строки свой.
- **Точная дата = касание ядра (О2).** Петля: строка на каждое касание в окне (как лента); событие без касания в окне в дашборд не попадает. Письмо и бриф — на событие: общие `touches_ru` / `period_ru`.
- **Порядок:** (1) PR — CRM в cB: функции расчёта вынести из ручек (как `window_events`), проверка — даты строк против касаний истины в поясе карты клиента, разбивка (станция / другой день / пояс-UTC / точка Юж. узел-ASC-MC / нет в CRM); прогон — база. (2) PR 4.12 под флагом (флаг — по владельцу-астрологу), без флага как было.
- **Попутно (не 4.12, решить):** письмо клиентам — английские «Saturn square Sun» в тексте и ISO-дата; голос — астролога («вы»).
